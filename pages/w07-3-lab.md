# 07주차 선택 과제 · 세 가지를 따로 재고 경계를 그려 보기

> **이 과제는 선택이다.** 7주차는 1교시 강의 뒤 곧바로 중간고사가 이어지므로 실습 시간이 없다. 시험이 끝난 뒤 여유가 있을 때 해 보라. 기말 캡스톤에서 구조를 직접 고를 팀에게 특히 권한다.
> **시험 범위가 아니다.** 다만 1교시에서 본 숫자를 직접 재현해 보면 이후 주차가 훨씬 쉬워진다.

> **준비물** — 1주차 환경(`odai`) + `torch` + `scipy`. GPU는 필요 없다. 1교시의 모든 숫자는 **CPU 2코어**에서 나온 것이다.

---

## 1. 탐색 공간을 코드로 정의하기

NAS의 첫 번째 요소는 **탐색 공간**이다. 사람이 정하는 부분이고, 사실 이 과제에서 가장 중요한 결정이다.

1교시에서 쓴 공간은 여섯 축의 조합이다.

```python
SPACE = {
    "w0":     [8, 12, 16, 24, 32],   # 첫 스테이지 채널 수
    "depth":  [2, 3, 4],             # 스테이지 개수
    "k":      [3, 5],                # 커널 크기
    "sep":    [False, True],         # 깊이별 분리 합성곱 사용 여부
    "expand": [1.5, 2.0],            # 스테이지마다 채널이 몇 배로 늘어나는가
    "head":   ["gap", "flatten"],    # 전역 평균 풀링 vs 평탄화
}
# 5 × 3 × 2 × 2 × 2 × 2 = 240 개
```

240개는 전수 조사도 가능한 크기다. 실제 NAS 논문의 탐색 공간은 $10^{18}$ 을 넘지만, **원리를 보는 데는 240개면 충분하다.**

> **관찰 포인트** — `sep` 축을 넣은 것이 이 공간의 핵심이다. **이 축 하나가 1교시의 모든 반전을 만든다.** 축 하나를 넣고 빼는 결정이 결과를 지배한다는 사실 자체가 **탐색 공간 설계가 왜 중요한지**를 보여 준다.

## 2. 학습 없이 잴 수 있는 것 두 가지

**연산량**과 **지연**은 학습 없이 잴 수 있다. 이 점이 중요하다 — 48개를 다 학습시키는 데는 25분이 걸리지만, 앞의 둘만 재는 데는 **1초**면 된다.

### 2.1 연산량 (MACs) — 종이 위에서 센다

```python
def flops_of(g):
    """곱셈-누산(MAC) 횟수. 배치 1 기준."""
    chans, c = [], g["w0"]
    for _ in range(g["depth"]):
        chans.append(int(round(c))); c *= g["expand"]
    macs, cin, size, k = 0, 1, 28, g["k"]
    for cout in chans:
        out = size                                   # padding='same' 이므로 공간 크기 유지
        if g["sep"]:
            macs += cin * k * k * out * out          # depthwise
            macs += cin * cout * out * out           # pointwise
        else:
            macs += cin * cout * k * k * out * out
        cin, size = cout, size // 2
    macs += cin * 10 if g["head"] == "gap" else cin * size * size * 10
    return macs
```

깊이별 분리 합성곱이 왜 연산량이 적은지가 코드에 그대로 보인다. 일반 합성곱의 `cin × cout × k × k` 가 `cin × k × k` 와 `cin × cout` 의 **합**으로 쪼개진다. **곱이 합이 되니** 확 줄어든다.

### 2.2 지연 — 실제로 돌려서 잰다

```python
@torch.no_grad()
def latency_ms(m, x, n=120, warmup=25):
    m.eval()
    for i in range(warmup):          # 워밍업 — 첫 몇 회는 항상 느리다
        m(x[i:i+1])
    ts = []
    for i in range(n):
        t0 = time.perf_counter()
        m(x[i % len(x):i % len(x)+1])
        ts.append((time.perf_counter() - t0) * 1000)
    return float(np.median(ts))      # 평균이 아니라 중앙값
```

> **자주 틀리는 곳 셋**
> 1. **워밍업을 빠뜨리면** 첫 호출의 메모리 할당·커널 선택 비용이 섞여 들어간다.
> 2. **평균이 아니라 중앙값**을 쓴다. 다른 프로세스가 끼어든 한 번이 평균을 통째로 망친다.
> 3. **스레드 수를 고정**한다(`torch.set_num_threads(2)`). 안 하면 실행할 때마다 값이 달라져 비교가 무의미해진다.

## 3. 세 가지를 재고 상관을 본다

```python
import numpy as np
from scipy.stats import spearmanr

rng = np.random.RandomState(7)
rows = []
for i in range(48):
    g = sample(rng)
    torch.manual_seed(1000 + i)        # ← 모델 초기값까지 고정할 것
    m = Candidate(g)
    rows.append((flops_of(g), n_params(m), latency_ms(m, xte)))

mac, par, lat = (np.array(c, float) for c in zip(*rows))
print("Spearman  연산량~지연   :", spearmanr(mac, lat).statistic)
print("Spearman  파라미터~지연 :", spearmanr(par, lat).statistic)
```

1교시에서 얻은 값이다.

| | Spearman (순위 상관) | Pearson (선형 상관) |
|---|---:|---:|
| 연산량 ~ 지연 | **0.301** | 0.681 |
| 파라미터 ~ 지연 | 0.332 | 0.749 |

> **왜 두 상관이 이렇게 다른가** — Pearson은 **값의 크기**가 대체로 함께 커지는지를 보고, Spearman은 **순위가 일치**하는지를 본다. 연산량이 100배 큰 모델이 지연도 대체로 크긴 하다(Pearson 0.681). 그러나 **"이 둘 중 어느 쪽이 더 빠른가"** 를 물으면 거의 못 맞힌다(Spearman 0.301).
>
> **NAS가 하는 일은 후보들의 순위를 매기는 것**이다. 그러니 여기서 중요한 것은 Spearman 쪽이다. 논문에서 상관계수를 볼 때 **어느 쪽인지 반드시 확인하라.**

### 역전 쌍을 세어 보기

```python
inv = sum(1 for a in range(len(mac)) for b in range(len(mac))
          if mac[a] < mac[b] and lat[a] > lat[b])
print(f"연산량이 적은데 더 느린 쌍: {100*inv/(len(mac)*(len(mac)-1)):.1f}%")
# → 19.5%
```

## 4. 파레토 경계를 그린다

```python
def pareto_front(points):
    """points: [(지연, 정확도, 인덱스)] — 지연은 작을수록, 정확도는 클수록 좋다."""
    front = []
    for lat_, acc_, i in sorted(points):        # 지연 오름차순
        if not front or acc_ > front[-1][1]:    # 지금까지의 최고 정확도를 넘을 때만
            front.append((lat_, acc_, i))
    return front
```

세 줄이면 된다. 지연이 작은 것부터 훑으면서 **"지금까지 본 것보다 정확한가"** 만 물으면, 살아남는 점들이 곧 경계다.

48개 중 경계에 오른 것은 **셋뿐**이었다.

| | 지연 | 정확도 | 연산량 |
|---|---:|---:|---:|
| `w12·d3·k3·std·e2.0·flatten` | **0.157 ms** | 87.96 % | 1,105,056 |
| `w16·d3·k3·std·e2.0·flatten` | 0.193 ms | 88.49 % | 1,924,992 |
| `w32·d2·k5·std·e2.0·flatten` | 0.426 ms | **89.57 %** | 10,693,760 |

나머지 45개는 **누군가에게 모든 면에서 지는** 후보들이다. 그렇다고 만들어 본 것이 낭비는 아니다 — **경계가 어디인지는 경계 밖을 봐야 알 수 있다.**

## 5. 과제

1. **재현** — 1교시의 세 숫자(순위 상관 0.301 · 역전 쌍 19.5% · MAC당 7.6배)를 재현하라. 여러분의 기기에서는 다른 값이 나올 것이다. **얼마나 다른지**와 **왜 다를 것 같은지**를 함께 적어라.
2. **`sep` 축을 빼고 다시** — 탐색 공간에서 `"sep": [False]` 로 고정하고 48개를 다시 뽑아 상관을 재라. 상관이 얼마나 올라가는가? 그 결과를 근거로 *"연산량을 대리 지표로 써도 된다"* 고 결론지어도 되는가?
3. **목적 함수를 바꿔 가며** — 아래 세 기준으로 각각 최적 후보를 고르고 표로 비교하라. 세 기준이 **같은 모델을 고르는가?**
   - (a) 정확도만
   - (b) 연산량만 (작을수록 좋음)
   - (c) 지연 ≤ 0.20 ms 제약 아래 정확도 최대
4. **MnasNet 보상 구현** — $ACC(m) \times \left[LAT(m)/T\right]^{w}$ 를 구현하고 $T = 0.20$ ms, $w = -0.07$ 로 48개 후보의 점수를 매겨라. 3번 (c)와 같은 모델이 뽑히는가? $w$ 를 $-0.5$, $-2.0$ 으로 바꾸면 어떻게 되는가?
5. **다른 축 추가** — 탐색 공간에 축을 하나 더 넣어라(예: 활성화 함수, 잔차 연결 유무, 스트라이드 위치). 그 축이 **파레토 경계를 바꾸는가?** 경계를 바꾸지 못하는 축은 탐색 공간에 넣을 가치가 있는가?
6. **정직한 보고** — 결과를 한 페이지로 정리하되 **측정 조건**(CPU 모델, 스레드 수, 배치 크기, 측정 횟수)을 반드시 명시하라. 4주차 과제 4번, 5주차 과제 4번과 같은 요구다.
7. **캡스톤 연결** — 여러분의 캡스톤 목적 함수를 적어 보라. 정확도 외에 무엇을 넣을 것인가? **넣지 않기로 한 것**은 무엇이고, 그것이 나중에 문제가 될 가능성은 어느 정도인가?

## 6. 이 과제에서 가져갈 것

> **NAS를 돌리지 않아도 NAS의 교훈은 쓸 수 있다.**

여러분 대부분은 캡스톤에서 NAS를 돌리지 않을 것이다. GPU가 없고 시간도 없다. 그래도 이 과제의 세 가지는 그대로 쓸 수 있다.

1. **후보를 몇 개 만들어 세 가지를 따로 재 본다** — 학습 없이 1초면 된다.
2. **파레토 경계를 그린다** — 세 줄짜리 함수면 된다.
3. **목적 함수를 명시적으로 적는다** — 무엇을 넣었고 무엇을 뺐는지.

이 셋만 해도 *"제일 좋아 보이는 걸 골랐습니다"* 보다 훨씬 나은 보고서가 된다.

> 한 줄 정리: 탐색 전략이 없어도 **재는 습관**과 **경계를 그리는 습관**은 오늘부터 쓸 수 있다.
