# 7주차 3교시. 탐색 공간 정의와 NAS 체험

**실습 목표** — NAS의 3대 요소를 코드로 체감한다. **탐색 공간**을 정의하고, **제약(파라미터 예산)** 을 걸어, 간단한 **탐색 전략(랜덤 서치)** 으로 후보를 골라 본다. 전체 NAS를 돌리는 대신, 그 뼈대를 손으로 만든다.

> 준비물: 1주차 환경(`odai`) + `torch`. 무거운 NAS 라이브러리 없이 원리를 체험한다.

---

## 3.1 탐색 공간·제약 정의 (20분)

1교시의 3대 요소를 그대로 코드로 옮긴다: **탐색 공간(SPACE)**, **성능/비용 지표(파라미터 수)**, **제약(예산)**.

```python
import random, torch.nn as nn
random.seed(0)

# ① 탐색 공간(Search Space): 각 선택지의 후보
SPACE = {"c1": [16, 32, 48], "c2": [32, 64, 96], "depth": [1, 2, 3]}
PARAM_BUDGET = 60_000         # 제약: 파라미터 수 상한(하드웨어 예산 대용)
                              #  ↑ 이 값이 커서 전부 통과하면 제약이 무의미해진다.
                              #    일부만 통과하도록 잡는 것이 핵심(값을 바꿔가며 관찰).

def build(cfg):               # cfg → 실제 모델
    layers = [nn.Conv2d(3, cfg["c1"], 3, padding=1), nn.ReLU()]
    for _ in range(cfg["depth"]):
        layers += [nn.Conv2d(cfg["c1"], cfg["c1"], 3, padding=1), nn.ReLU()]
    layers += [nn.Conv2d(cfg["c1"], cfg["c2"], 3, padding=1), nn.ReLU(),
               nn.AdaptiveAvgPool2d(1), nn.Flatten(), nn.Linear(cfg["c2"], 10)]
    return nn.Sequential(*layers)

def n_params(m): return sum(p.numel() for p in m.parameters())
def sample():    return {k: random.choice(v) for k, v in SPACE.items()}
```

> 관찰 포인트: `PARAM_BUDGET`이 곧 하드웨어 제약의 대용이다. 실제 Hardware-aware NAS라면 여기에 **실측 지연**이 들어간다(2교시).

## 3.2 NAS 도구 체험 — 제약 하 랜덤 서치 (20분)

정의한 공간에서 후보를 무작위로 뽑아, **제약을 만족하는 것만** 남기고 비용순으로 정렬한다(가장 단순한 탐색 전략).

```python
found = []
for _ in range(30):                     # 탐색 전략: 30회 랜덤 샘플
    cfg = sample(); n = n_params(build(cfg))
    if n <= PARAM_BUDGET:               # 제약 필터
        found.append((n, cfg))

found.sort()                            # 파라미터가 적은(가벼운) 순
print(f"제약 통과 후보: {len(found)}개")
for n, cfg in found[:5]:
    print(f"{n:>8,} params  {cfg}")
```

이 작은 예제가 NAS의 뼈대다: **공간 정의 → 샘플(전략) → 제약·비용으로 평가**. 실제 NAS는 여기에 (1) 훨씬 큰 공간, (2) RL/EA/Gradient 같은 똑똑한 전략, (3) 파라미터가 아니라 **정확도+실측 지연** 기반의 성능 예측을 더한 것이다.

> 관찰 포인트: 여기서는 성능 지표로 '파라미터 수'만 썼지만, 실제로는 정확도까지 추정해야 한다. 그래서 NAS의 진짜 비용은 **성능 예측(3요소 중 ③)** 에서 나오며, OFA·가중치 공유가 그 비용을 줄이는 열쇠다.

**실무 도구 안내** — 대규모 탐색에는 **NNI(Neural Network Intelligence)** 나 **Auto-Keras** 같은 라이브러리를 쓴다. 이들은 탐색 공간 정의, 전략(RL/EA/베이지안 등), 성능 예측, 병렬 실행을 프레임워크로 제공한다.

## 3.3 과제 및 중간고사 안내 (10분)

1. **탐색 공간 확장** — `SPACE`에 커널 크기(`k`: 3, 5)나 스테이지 수를 추가하고, `PARAM_BUDGET`을 바꿔가며 제약 통과 후보 수가 어떻게 변하는지 표로 제출한다.
2. **비용-공간 해석** — 예산을 줄이면 어떤 선택지가 먼저 탈락하는가? 이를 2교시의 Pareto 개념과 연결해 3~4문장으로 서술한다.
3. **탐색 전략 비교 조사** — RL·EA·Gradient(DARTS) 중 하나를 골라, 장단점과 대표 논문을 한 문단으로 정리한다.
4. **8주차 중간고사 대비** — 시험 범위는 **1~7주차**다: 하드웨어 아키텍처(2주), 프레임워크·그래프 최적화(3주), 경량화 3부작(프루닝·양자화·지식 증류, 4~6주), NAS(7주). 각 주차의 "한 줄 정리"와 핵심 키워드를 중심으로 복습할 것.

> 교수님을 위한 Tip: 랜덤 서치조차 "공간·전략·평가"의 삼각 구조를 그대로 갖는다는 점을 강조하라. 학생이 이 뼈대를 이해하면, DARTS·OFA 같은 고급 기법도 "삼각형의 어느 꼭짓점을 개선한 것인가"로 정리할 수 있다.
