연합 학습에서 기기가 서버로 보내는 것은 이것이다.

```python
def grads(x, y):
    """이 기기가 서버로 보내는 것 — 데이터가 아니라 이것이다."""
    return [g.detach() for g in
            torch.autograd.grad(Fn.cross_entropy(m(x), y), list(m.parameters()))]
```

모델은 MLP(784 → 32 → 10), 25,450개 파라미터다.

## 3.2 나눗셈 한 번 (14분)

### 종이 위에서 먼저

$z = Wx + b$ 이면

$$\frac{\partial L}{\partial W} = \underbrace{\frac{\partial L}{\partial z}}_{\delta}\, x^{\top}, \qquad \frac{\partial L}{\partial b} = \underbrace{\frac{\partial L}{\partial z}}_{\delta}$$

첫 번째 식은 "$\delta$ 곱하기 $x$", 두 번째 식은 "$\delta$". 나누면 $x$ 다.

### 코드로

```python
def invert(gW, gb):
    i = int(gb.abs().argmax())      # 나눗셈이 가장 안정적인 행
    return gW[i] / gb[i]            # ← 이 한 줄이 전부다
```

`gb.abs().argmax()` 를 쓰는 이유는 하나다. 분모가 0에 가까우면 수치가 터진다. **가장 큰 분모를 고르는 것**이 안전하다.

### 결과

```
② 복원 PSNR 167.7 dB · 최대 화소 오차 1.2e-07
   반복 최적화가 아닙니다. 나눗셈 한 번입니다.
```

![기울기 하나에서 원본이 그대로 나온다](../assets/w12_p2_invert_05.png)

**PSNR 167.7 dB.** 사진 압축에서 40 dB 면 "원본과 구분 불가"라고 한다. 167 dB 는 그 차원이 아니다 — **float32 가 표현할 수 있는 한계까지 같다.**

### 라벨도 함께

```python
ok = sum(int(grads(X[i:i+1], Y[i:i+1])[3].argmin()) == int(Y[i]) for i in range(50))
```

마지막 층 편향 기울기 $\partial L/\partial b_L = p - \text{onehot}(y)$ 에서 **정답 클래스 성분만 음수**다. `argmin` 하나면 된다.

```
③ 라벨 복원 50/50 — 마지막 층 편향 기울기가 음수인 자리가 정답입니다
```

> **50/50 입니다.** 이미지와 라벨이 함께 나왔으면, 그 기기의 학습 데이터를 그대로 가진 것입니다.

## 3.3 그러면 어떻게 막나 — 두 번 틀리고 한 번 맞기 (16분)

### 첫 번째 시도 — 배치를 키운다

```python
for B in [1, 4, 16, 32]:
    gb = grads(X[:B], Y[:B])
    print(B, psnr(invert(gb[0], gb[1]), X[0]))
```

```
④ B=  1  개별 표본 대비 167.72 dB
   B=  4  개별 표본 대비  15.22 dB
   B= 16  개별 표본 대비  16.17 dB
   B= 32  개별 표본 대비  11.74 dB
```

**성공한 것처럼 보인다.** 그런데 교재 2.2 에서 우리는 같은 복원을 **$\delta$ 가중 평균**과 비교했다.

| 배치 | 개별 표본 대비 | **가중평균 대비** |
|---:|---:|---:|
| 32 | 12.39 dB | **151.81 dB** |

![배치는 누출의 양이 아니라 대상을 바꾼다](../assets/w12_p2_batch_06.png)

**복원은 실패하지 않았다.** 복원된 것이 "한 사람"에서 "32명의 가중 평균"으로 바뀌었을 뿐이다. 그리고 그 가중치는 우리가 고르는 것이 아니라 **손실이 정한다** — 어떤 표본이 평균을 지배할지는 통제 밖이다.

### 두 번째 시도 — 클리핑한다

```python
s = min(1.0, C / float(norm))
g2 = [t * s for t in g2]
```

```
⑤ C=1.0    배율 0.11351 → PSNR  153.01 dB
   C=0.01   배율 0.00114 → PSNR  152.88 dB
```

**배율 0.00114 — 기울기를 천 분의 일로 눌렀는데 복원은 그대로다.**

당연하다. 우리 식은 나눗셈이고, 분자와 분모에 같은 상수가 곱해지면 약분된다.

$$\frac{c \cdot gW[i]}{c \cdot gb[i]} = \frac{gW[i]}{gb[i]}$$

> **이것이 오늘 실습에서 학생이 직접 확인해야 할 가장 중요한 한 줄입니다.** DP-SGD 의 클리핑은 프라이버시를 주는 장치가 아니라 **민감도의 상한을 정하는 장치**입니다. 프라이버시는 다음 단계에서 옵니다.

### 세 번째 시도 — 노이즈

```python
g2 = [t + torch.randn_like(t) * sig for t in g2]
```

```
⑥ σ=0.0    PSNR  153.01 dB
   σ=0.001  PSNR   35.35 dB
   σ=0.01   PSNR   19.84 dB
   σ=1.0    PSNR    8.91 dB
```

![노이즈만이 유일하게 듣는다](../assets/w12_p2_noise_08.png)

**드디어 막혔다.** 그리고 여기서 대부분 멈춘다.

## 3.4 여기서 멈추면 안 되는 이유 (8분)

$\sigma = 0.01$ 로 공격을 막았고 정확도 손실도 거의 없었다. 좋은 거래처럼 보인다. 그런데 그 $\sigma$ 의 $\varepsilon$ 을 계산해 보면

```python
from opacus.accountants import RDPAccountant
a = RDPAccountant()
for _ in range(260):
    a.step(noise_multiplier=0.01, sample_rate=0.0794)
print(a.get_epsilon(delta=1e-5))      # 1422866.82
```

$$\varepsilon = 1{,}422{,}867$$

![공격을 막는 것과 보장을 얻는 것은 값이 다르다](../assets/w12_p2_tradeoff_09.png)

| $\sigma$ | 복원 | $\varepsilon$ | 정확도 손실 |
|---:|---|---:|---:|
| 0.01 | 파괴 | **1,422,867** | **0.00%p** |
| 1.0 | 파괴 | 9.83 | 1.05%p |
| 2.0 | 파괴 | **3.27** | **3.50%p** |

**공격을 막는 것은 공짜였다. 보장을 얻는 것은 3.5%p였다.**

$e^{1422867}$ 은 어떤 두 확률의 비도 제약하지 않는다. $\sigma$=0.01 은 **우리가 방금 짠 이 공격**을 막았을 뿐, 다음 사람이 짤 공격에 대해서는 아무것도 약속하지 않는다.

> **이것이 이번 주차의 결론입니다.** 실습 보고서에 이 문장이 들어가야 합니다 — **"우리는 이 공격을 막았다"와 "우리는 보장을 갖는다"는 다른 명제다.**

### 선택 A — 합성곱으로 바꿔 본다

첫 층을 `nn.Conv2d` 로 바꾸고 같은 공격을 시도하십시오. **왜 더 어려워집니까?** (힌트: 합성곱 필터는 입력 특징을 겹쳐 놓습니다.) 그리고 **어려워진 것과 불가능해진 것은 같습니까?**

### 선택 B — 어느 표본이 평균을 지배하는가

배치 32에서 복원되는 것은 $\delta$ 가중 평균입니다. 각 표본의 가중치 $\delta_b[i]$ 를 직접 뽑아 **어떤 표본이 지배하는지** 조사하십시오. 손실이 큰 표본입니까, 작은 표본입니까? 그것이 프라이버시 관점에서 무엇을 뜻합니까?

### 선택 C — $\varepsilon$ 곡선을 직접 그린다

`opacus` 의 `RDPAccountant` 로 $\sigma \in [0.5, 4]$ 구간의 $\varepsilon$ 을 계산하고, 같은 축에 정확도를 그리십시오. **여러분 응용에서 받아들일 수 있는 $\varepsilon$ 은 얼마이고, 그때 정확도는 얼마입니까?**

### 선택 D — 표본 단위 클리핑을 직접 구현한다

`torch.func.vmap` 으로 표본별 기울기를 만들어 **표본마다** 클리핑하십시오. 그리고 **배치 단위 클리핑과 결과가 어떻게 다른지** 보이십시오. (왜 DP-SGD 가 표본 단위를 요구하는지 여기서 알게 됩니다.)

### 3교시 정리
- 연합 학습이 보내는 것은 기울기이고, 선형층 기울기는 **나눗셈 한 번**으로 입력을 돌려준다 — 실측 **167.7 dB**, 최대 화소 오차 **1.2×10⁻⁷**.
- 라벨은 `argmin` 하나로 나온다 — **50/50**.
- **배치는 누출의 대상을 바꿀 뿐**이다. 가중평균 대비로는 배치 32에서도 151.81 dB.
- **클리핑의 방어력은 0** 이다. 배율 0.00114 에서도 152.88 dB.
- 노이즈만 듣는다. 그러나 **$\sigma$=0.01 의 $\varepsilon$ 은 1,422,867** — 공격을 막은 것이지 보장을 얻은 것이 아니다.
- 보장($\varepsilon$=3.27)의 값은 **정확도 3.50%p** 였다.

### 교수님을 위한 Tip
**3.2 는 코드를 먼저 보여 주지 마십시오.** 칠판에 $\partial L/\partial W = \delta x^{\top}$ 와 $\partial L/\partial b = \delta$ 두 줄만 쓰고 5분 기다리시면, 반에서 누군가는 반드시 "나누면 되는데요?" 라고 말합니다. 그 순간이 이 과목 전체에서 가장 좋은 순간입니다.

**3.3 의 세 시도는 순서가 중요합니다.** 배치 → 클리핑 → 노이즈 순으로, **앞의 두 개는 학생이 제안하게** 하십시오. 자기가 제안한 방어가 실측으로 깨지는 경험이 설명보다 열 배 오래 갑니다.
