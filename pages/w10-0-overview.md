# 10주차. 엣지 기반 언어 지능 및 On-Device LLM

> Language Intelligence on the Edge & On-Device LLM
> 주당 3시간 · 3교시 × 약 50분 · 이론 70% / 실습 30%

## 이 주차의 성격

9주차에서 우리는 시야를 모델 바깥으로 넓혔다. 파이프라인 일곱 단계, 암달의 벽, 프레임 나이. 이번 주는 그 관점을 **언어 모델**로 옮기는데, 여기서는 시야를 넓힐 것도 없이 **모델 안에서** 두 개의 완전히 다른 기계가 발견된다.

> **프리필은 438.9 tok/s, 디코드는 22.0 tok/s. 같은 모델, 같은 CPU, 20배 차이.**

그리고 이번 주의 두 번째 발견은 우리말과 직접 맞닿아 있다.

> **같은 모델이 영어로는 읽는 속도보다 4.85배 빠르고, 한국어로는 못 따라간다(0.64배).** 모델은 한 글자도 안 바뀌었고, 바뀐 것은 토크나이저가 우리 언어를 몇 조각으로 쪼개는가뿐이다.

**이번 주는 앞선 주차의 결론이 두 번 뒤집힌다.** 9주차에서 실패했던 양자화가 여기서는 성공하고, 9주차에서 나쁜 거래였던 배치가 여기서는 좋은 거래가 된다. 둘 다 **기법이 바뀌어서가 아니라 작업이 무엇에 묶여 있는지가 달라서**다. 그 구분을 **연산 강도**라는 하나의 개념으로 설명하는 것이 이번 주의 학술적 목표다.

**응용 세 번째 주차**다. 8주차는 자원 제약(메모리·전력), 9주차는 시간 제약, 10주차는 **대역폭 제약**을 다룬다.

> **강의 운영 메모** — 이번 주의 두 반전(1.2 의 20배, 1.3 의 한국어 0.64배)은 모두 **먼저 예측시키고 나서 표를 여는** 방식으로 써 두었습니다. 특히 1.3 은 영어 줄만 먼저 보여 주고 "우리 수업 자료는 한국어인데 어떨까요?"로 여시면 효과가 가장 큽니다. 3교시는 **GPU 도 API 키도 없이** 노트북만으로 완결되며, 모델은 Apache-2.0 이라 9주차의 AGPL 문제가 없습니다.

## 학습 목표
- **프리필과 디코드**를 구분하고, 왜 하나는 병렬이 되고 하나는 안 되는지 설명할 수 있다.
- **TTFT 와 TPOT** 를 따로 측정하고, 사용자가 겪는 지연을 두 값으로 분해할 수 있다.
- **연산 강도**와 **루프라인**으로 어떤 작업이 무엇에 묶여 있는지 판정할 수 있다.
- 가중치 전용 양자화가 **왜 어떤 작업은 빠르게 하고 어떤 작업은 느리게 하는지** 설명할 수 있다.
- **KV 캐시** 크기를 계산하고 실측으로 검증하며, GQA 의 이득을 정량화할 수 있다.
- 배치의 교환비가 **작업의 성질에 따라 뒤집히는** 이유를 설명할 수 있다.
- 자기 응용의 **토큰 예산**을 실제 토크나이저와 실제 문장으로 세울 수 있다.
- 서빙 시스템(반복 수준 스케줄링·PagedAttention)이 푸는 문제를 설명하고, 그 수치를 **조건과 함께** 인용할 수 있다.

| 교시 | 성격 | 하위 목차 | 배정(분) |
|:---:|------|-----------|:---:|
| **1교시** | 개론 | 1.1 하나의 숫자가 두 개의 연산을 감춘다 / 1.2 프리필과 디코드는 사실상 다른 기계다 / 1.3 그래서 얼마나 빠르면 되는가 | 50 |
| **2교시** | 심화 | 2.1 대역폭 가설을 검증한다 / 2.2 KV 캐시 — 두 번째 메모리 / 2.3 배치 — 9주차 결론이 뒤집힌다 / 2.4 그래서 서빙 시스템은 무엇을 하나 / 2.5 [더 깊이] 디코드를 병렬로 만들 수 있을까 | 50 |
| **3교시** | 실습 | 3.1 프리필과 디코드를 갈라 놓는다 / 3.2 대역폭 가설을 검증한다 / 3.3 KV 캐시와 내 언어의 예산 / 3.4 과제 | 50 |

*(3교시 제목은 「내 노트북에서 LLM을 쪼개서 재 보기」 — 결론을 제목에 담지 않는다.)*

## 이 주차에서 쓰는 비유 (강의 중 그대로 활용 가능)
- **한 트럭에 한 개씩 싣기** — 배치 1 디코드. 트럭을 부르는 비용(가중치 읽기)은 같은데 짐이 하나뿐이다. **이번 주의 중심 비유.**
- **바이트당 몇 번 계산하는가** — 연산 강도. 165가 필요한 자리에 1을 들고 온 상황.
- **줄일 것은 계산이 아니라 실어 나를 짐** — 가중치 전용 양자화가 하는 일.
- **뒤에 앉은 사람들이 트럭 값을 나눠 낸다** — 배치가 LLM 에서 이득인 이유.
- **같은 문장, 다른 조각 수** — 토크나이저. 영어는 25단어를 30조각, 한국어는 16단어를 145조각으로 쪼갠다.

## 체감시킬 숫자 세 개
- **20배** — 같은 모델·같은 CPU 에서 프리필(438.9 tok/s)과 디코드(22.0 tok/s)의 처리량 차이. 원인은 **연산 강도 약 1**.
- **1.52배 느려짐 → 1.57배 빨라짐** — 같은 동적 INT8 양자화가 9주차 탐지 모델과 10주차 LLM 디코드에서 낸 정반대의 결과.
- **4.85배 여유 vs 0.64배 미달** — 같은 모델이 영어와 한국어에서 읽는 속도를 따라가는 정도. 바뀐 것은 **토크나이저뿐**이다.

## 선수·후속 연결
- **1주차에서 이어짐** — `.eval()` 과 워밍업이 3교시 측정 절차에 그대로 나온다.
- **2주차에서 이어짐** — 메모리 벽이 여기서 **성능 상한 그 자체**가 된다. 루프라인이 2주차의 논의를 정량화한다.
- **5주차와 9주차를 잇는다** — 양자화가 5주차에서 조건부, 9주차에서 실패, 10주차에서 성공한다. **세 결과를 하나의 개념(연산 강도)으로 설명하는 것이 이번 주의 정점이다.**
- **8주차에서 이어짐** — 8주차의 텐서 수명 기반 메모리 계획과 PagedAttention 을 비교하면 좋다(2교시 토론 4번).
- **9주차와 정면으로 대비됨** — 배치가 9주차에서는 처리량 1.24배에 지연 6.5배(나쁜 거래), 여기서는 3.9배에 2.06배(좋은 거래)다.
- **11주차로 이어짐** — 가속기 툴체인이 붙으면 분모와 대역폭이 모두 바뀐다. 2.1 의 판정을 그 환경에서 다시 해야 한다.
- **14주차 캡스톤** — 한국어 LLM 응용을 잡는 팀은 **첫 주에 토큰 예산부터** 세우십시오. 3교시 여덟 줄이면 됩니다.

## 이 주차의 데이터·재현 정보
- **모델** — `HuggingFaceTB/SmolLM2-135M-Instruct`(Ben Allal 외, COLM 2025). 파라미터 134,515,008 · 30층 · hidden 576 · 질의 헤드 9 · KV 헤드 3(GQA 3:1) · 어휘 49,152 · 최대 문맥 8,192 · **Apache-2.0**.
- **환경** — CPU 2스레드(`torch.set_num_threads(2)`), FP32, `transformers`. 워밍업 후 중앙값.
- **주의 1** — 135M 모델의 결과가 7B 모델로 그대로 확장되지는 않는다. 다만 **연산 강도로 판정한다**는 방법은 크기와 무관하다.
- **주의 2** — 절대값은 재실행 시 크게 흔들린다. 이 문서를 만들며 프리필/디코드 비가 **18~24배**, 양자화 이득이 **1.57~1.72배** 사이에서 움직였다. 재현을 요구하는 것은 **구조**다.
- **주의 3** — 구조 수치는 논문이 아니라 **모델 카드/`config.json`** 에서 인용해야 한다. SmolLM2 논문의 하이퍼파라미터 표는 1.7B 판의 것이다.
